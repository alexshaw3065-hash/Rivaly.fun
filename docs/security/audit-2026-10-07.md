# Security review — 2026-10-07

An internal review of the on-chain rooms program and the app's money paths, done while switching new rooms to the program. **Not a professional audit:** it doesn't replace one, which is required before mainnet. Never describe Rivaly as "audited" on the strength of this.

## Scope

- `onchain/programs/rivaly_rooms` (the program): every instruction, account constraint and arithmetic path.
- The app's money paths: staking (`rooms/actions.ts`, `verify-stake-tx.ts`, `program.ts`), settlement (`settle.ts`, `settle-program.ts`), recovery, host claims (`wallet/actions.ts`), Rivaly fee withdrawals and admin actions (`admin/actions.ts`), the sign-up grant, how wallet addresses get onto accounts (`auth/*`), cron and API routes, and the database's row-level security on every money table.

## How it was tested

- 41 program tests on a local chain (LiteSVM): 29 refusals each asserting the specific error, 10 attack/edge cases, a smoke run, and a parity run of 400 random rooms (2,516 people) whose payouts are compared entry by entry with the app's `planSettlement`.
- Devnet end-to-end with the app's own code (`onchain/scripts/devnet-e2e.mts`) and a settlement rehearsal with `payProgramRoom` itself (`devnet-settle-rehearsal.mts`).
- Code reading of every server action, API route and money-moving call site; database policy and grant inspection.

## What holds

| Area | Finding |
|---|---|
| Program: where money can go | Only to a position's owner (winnings/refunds) and, at close, fees to the configured treasury and the rounding leftover to a named winner. Account substitution (another room's vault or position, another owner's USDC account, a fake treasury, Token-2022 in place of Token, a different mint) is refused. |
| Program: double payment | A paid position is closed; paying it again — in a later transaction or twice in the same one — fails. Re-running settlement pays nothing. |
| Program: maths | Matches `planSettlement` to the cent across 400 random rooms, including ties, voids, one-sided rooms, expiries and fees from 0% to 25%. Every unit is conserved; rent comes back. |
| Program: liveness | An unresolved room can be voided by anyone after its expiry (kick-off + 14 days) and everyone refunded, even if Rivaly is gone. |
| Program: setup | Only the upgrade authority can initialise; only the admin can rotate keys. |
| Stakes | The server builds every stake; the escrow co-signs only a transaction identical to what it built (extras limited to capped compute-budget and read-only Lighthouse assertions). A stake altered by the wallet is refused (tested on devnet). |
| Wallet addresses | Set only from a server-verified Dynamic token, never changed once set; users have no update right on the column. |
| Database | RLS on every money table; users can read only their own rows and write none of them. Security-definer functions callable by users don't move money. |
| Server actions / API | Every money action checks the session; host claims and fee withdrawals take amounts from the database, never the client. Cron routes need the secret; the data API needs a partner key. No browser code imports key-holding modules; no secret is in a public variable. |
| Admin login | Constant-time password check, signed HTTP-only same-site-strict cookie, per-IP and global rate limits. |

## Fixed in this review

1. **Health and finance pages counted program-room stakes as owed by the escrow wallet** — they would have shown "SHORT" once program rooms existed. Now they count wallet rooms only, plus two new checks: escrow SOL low, and every open program room's vault matching the database.
2. **Escrow SOL could be tied up by room spam.** Each program room's rent (~0.006 SOL) is fronted by the escrow until it settles; many $1 rooms (e.g. from farmed sign-up grants) could drain it and stop all stakes. Now: at most 20 open rooms per creator, and the SOL alert above.
3. **Cron secret compared with `!==`.** Now constant-time (`src/lib/cron-auth.ts`).
4. **Fees recorded before reaching the treasury** for program rooms (fixed earlier the same day).
5. **A stake-floor trigger bug blocked every stake 07:02–22:11 UTC** (fixed the same day; all seven affected stakes were refunded automatically). Process change: any database change touching rooms or stakes gets a dry-run room creation and join.

## Second review — 2026-10-08

| Finding | Status |
|---|---|
| Expiry and fees were whatever the server sent: no upper bound on expiry, 25% cap per fee while 5% is advertised. | **Fixed in the program, live on devnet** (upgraded 2026-10-08, slot 508718766; devnet-e2e passed): fees together ≤ 6% of the winners' profit; stakes close ≤ 180 days after a room opens; a room expires ≤ 21 days after stakes close, then anyone can void it. The app checks the same limits first. |
| The config admin couldn't be changed (no `set_admin`), so even a multisig upgrade authority leaves one laptop key able to swap the operator or treasury. | **Fixed in the program, live on devnet**: `propose_admin` → `accept_admin` (two-step, the new admin must sign), `cancel_admin_transfer`. Moving the admin and the upgrade authority to Squads: docs/security/squads-handover.md (needs the founder's multisig). |
| One key is operator, fee payer and treasury. | **Open — product call.** See below and squads-handover.md: host earnings are paid from the treasury. |
| Only HSTS was sent. | **Fixed**: CSP (`frame-ancestors 'none'; base-uri 'self'; object-src 'none'; upgrade-insecure-requests`), X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, HSTS with subdomains. A script CSP needs per-request nonces — later. |
| `/admin` served the ops login to anyone. | **Fixed**: every `/admin` URL is a 404 unless you're already an admin; the password form only exists at `/admin/login/<ADMIN_LOGIN_PATH>` (secret, from the environment), and the login action checks it too. |

## Open — decisions and work before mainnet

| Severity | Item |
|---|---|
| High (before mainnet) | **Program upgrade authority is one key on a laptop.** Whoever holds it can change the program's rules. Move it to a two-signature key (e.g. Squads) or freeze upgrades. |
| High (before mainnet) | **Professional audit** of the program and money paths. |
| High (business) | **Sign-up grant farming** with throwaway wallets — pay the grant only after a first real stake, or similar. |
| Medium | **The escrow key** still holds wallet-custody rooms' stakes (until they close), Rivaly's and hosts' unclaimed fees, pays network fees, and is the program's operator (decides results). If stolen: wallet-room stakes and the fee balance are at risk; program rooms can be resolved wrongly but their money can only go to their own stakers. Keep it only on Vercel, keep little in it, and consider separate operator / fee-payer / treasury keys. |
| Medium | **The ops password signs in as owner** with no second factor; owner can set Rivaly's fee wallet and withdraw fees, and add admins. Prefer named admin accounts with two-factor sign-in for money actions. |
| Low | The operator can refund an open room's position at any time before a result (used to undo unrecorded stakes); a compromised operator could use it to reshape a live room — but it already decides results, a bigger lever. Money still goes only to the position's owner. |
| Low | If Circle froze a winner's USDC account, that payout would fail and the room couldn't close until it's unfrozen (other payouts unaffected). |
| Info | Dynamic's confirm screen shows "N/A" for devnet USDC on every stake (not program-specific). |
